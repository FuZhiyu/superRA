## Objective

Add `skills/superplan/references/interactive-mode.md` defining the interactive canvas — a **light-plan → execute-yourself → record** loop, co-edited with the researcher, sized for concentrated work (not trivial jots). It spans a spectrum of plan/execute interleaving, all through the same task file:

- **Light-plan, then execute.** Lightly scope a target/objective into a task file (a light superplan — positioning retained, but skipping the full exploration / domain-gate / decomposition choreography), then execute yourself and record results in place.
- **Retroactive capture.** When the work is already done and the researcher asks to write it up (a handoff note, or a task reflecting what changed), run the same loop results-first via `references/task-tree-design.md §Retroactive Task-Tree Creation` — route the request through this loop rather than forking a parallel path.

Across the spectrum:

1. **Co-edit** targets and objectives into the task file via the `using-superra` §Task Interface.
2. **Self-review always** — apply domain judgment (e.g. Iron Law, evidence-before-claims for data work) as a genuine pass, not a heavy multi-item ceremony.
3. **Keep the task updated (required)** — record work into `## Results

[interactive-mode.md](../../../skills/using-superra/references/interactive-mode.md) carries the canvas loop, reached by one load condition from the de-crowded [superplan/SKILL.md](../../../skills/superplan/SKILL.md). The reference loads no role specs — it is itself the protocol — and is self-contained for a main agent running the whole spectrum.

- **Framing.** A fused light-plan → execute-yourself → record loop the main agent runs with the researcher, doing the work itself and pausing often. The selection axis is autonomy, not difficulty; it is an explicit opt-in, and not for trivial jots.
- **Spectrum.** Forward light-plan-then-execute keeps positioning and skips the exploration and decomposition choreography. Retroactive capture is the same loop run results-first, triggered by work already done that the researcher asks to write up; it routes to `task-tree-design.md §Retroactive Task-Tree Creation` rather than forking a parallel path.
- **Loop.** Co-edit the task file per `using-superra` §Task Interface; self-review always against the active domain skill's gated checklist; commit as you go; then ask review now, defer, or skip — reusing the existing status enum rather than inventing an awaiting-review state.
- **Two steps are required, not optional:** keep the task updated (record `## Results` and move `status` before each pause) and ask before review with a tool, never dispatching on your own read. Both were skipped the first time the mode was exercised, which is why they are stated as steps.
- **Positioning and intent.** Placement routes to `task-tree-design.md §Placing Work`. The confirm-intent gate for tree changes collapses when the human is the editor — their message is the authorization — and survives only for agent-initiated scope changes.
- **Dashboard pairing.** Live serve is recommended as a read-only canvas view; editing from the dashboard is out of scope.

The reference later moved to `using-superra/references/` when interactive became the default mode ([v04-lean-workflow/workflow-defaults](../../v04-lean-workflow/workflow-defaults/task.md)).
