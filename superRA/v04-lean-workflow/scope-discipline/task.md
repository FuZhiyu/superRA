## Objective

Add a deliver-what-was-asked contract so agents stop implementing beyond the task.

- Implement role skill carries the scope rule (adapting the Opus 5 guidance wording): deliver what was asked, at the scope intended; if the request seems mistaken or a better approach exists, say so in a sentence and continue as asked rather than quietly narrowing, widening, or transforming the work.
- Planner side (`task-tree-design.md`): objectives state when a task is deliberately open-ended; otherwise the objective's artifacts define scope and unrequested additions don't belong.
- Review side: scope fidelity is a named review focus (defined in `review-calibration`) — work beyond the objective is a reportable finding.
- Extend, don't duplicate, the existing `using-superra` §Code-Change Defaults (minimum code, surgical edits): those govern code edits; this contract governs task scope. One home per rule.
- Validation: the rule appears once per surface with pointers elsewhere; no restatement across role skill, planning reference, and using-superra.

## Planner Guidance

- Motivation: latest-generation agents guess at unstated wants, delivering unrequested work that then costs review and fixing.
- The Opus 5 doc's scope phrasing and the over-scoping findings: [review-prompting research](../attachments/research-review-prompting.md) §A and §D.
