## Objective

Make interactive main-agent execution the default workflow and independent review an execution-time decision, re-scoping `superimplement` as the explicitly-entered autonomous mode.

- Interactive default: on a built tree the main agent executes tasks itself (the canvas loop) without loading `superimplement`. `superimplement` becomes the autonomous subagent workflow, loaded only when the researcher requests it or accepts the agent's recommendation — recommend with a one-line rationale when the frontier is broad, parallelizable, or context-heavy; never silently switch.
- Review is decided on the fly by whoever orchestrates, with researcher input — not scheduled at planning. After a task completes, judge from the result's stakes and plausibility (and any implementer concern return) whether an independent pass is worth it and at which tier/focuses; when the researcher is present, recommend and ask rather than dispatch. Planners may suggest a review in `## Planner Guidance`; the suggestion does not bind.
- Define the approval transition when no review runs — the orchestrating agent sets `approved` after its own verification — and update the status-ownership sentence in `task-file-contract.md`, the resume semantics in `main-agent.md` §Resuming Work (`implemented` no longer universally means "to review"), and every unconditional review step in `superimplement`.
- Record what review an approved task actually got. At APPROVE the reviewer's tier/focus header goes away with `## Review Notes`, so an approved task carries no record of the depth and focus it was reviewed under — or of whether an independent pass ran at all. Under triggered review that record is load-bearing for the next reader; give it a durable home (the approving agent's commit body is the cheapest candidate).
- The INTEGRATE boundary keeps one thorough review of accumulated work as the safety net.
- Re-scope or verify `hooks/ensure-agent-orchestration` — it gates the `agent-orchestration` load for `superimplement`, which misfires when the default path dispatches nothing.
- Task-sizing instruction fixes live in the `planning-sizing` sibling (different edit surface: superplan references).
- Update the statements the flip invalidates: the `CLAUDE.md` "Gates are local discipline … enforced" principle (gates still bind when a review runs), and execution-mode/implement descriptions in `CLAUDE.md`, `README.md`, and `docs/site`.
- Validation: a fresh-session trace on a small tree runs interactive with zero dispatches and zero `superimplement` loads; a broad-frontier trace produces a subagent-mode recommendation; a completed high-stakes task produces a review recommendation naming tier and focuses.

## Planner Guidance

- Motivation: subagent-heavy execution is slow and implements/reviews things the researcher never wanted; high human cadence catches misdirection early.
- Choreography map with the unconditional-review lines: [review-architecture map](../attachments/map-review-architecture.md) §2; scheduling options and evidence: [review-prompting research](../attachments/research-review-prompting.md) §C.
- Interactive mode's "ask before review: now / defer / skip" (`superplan/references/interactive-mode.md`) is the precedent; the canvas loop likely moves out of superplan's references to a home both PLAN and IMPLEMENT enter.
- Seat assignment in `agent-orchestration` stays useful for the autonomous mode — re-scope it, don't delete it.

## Results

**Default flipped.** [main-agent.md §Execution Modes](../../../skills/using-superra/references/main-agent.md#L51-L54) now opens on **interactive** — the main agent executes the task itself through the canvas loop, no `superimplement` load, no dispatch — and demotes **subagent** to the opt-in, entered on researcher request or an accepted one-line recommendation (recommend when the frontier is broad, parallelizable, or context-heavy). [superimplement/SKILL.md](../../../skills/superimplement/SKILL.md#L6-L14) is re-titled and re-framed accordingly: entering it *is* subagent mode.

**Canvas loop moved to a home both phases enter**, [using-superra/references/interactive-mode.md](../../../skills/using-superra/references/interactive-mode.md) (was `superplan/references/`). `superplan` and `main-agent.md` point at the new path; the in-file relative pointers to `task-tree-design.md` / `changing-the-tree.md` were re-qualified after the move.

**Review is an execution-time call.** The new [§Deciding on Review](../../../skills/using-superra/references/main-agent.md#L58-L66) is the single home for the decision, read by the orchestrating main agent in both modes: judge stakes and plausibility, review on a researcher request / a planner high-stakes mark / an implementer concern / a load-bearing result you cannot verify from the evidence; recommend-and-ask when the researcher is present; **no review → verify yourself and set `approved`**. [superimplement Step 2.4](../../../skills/superimplement/SKILL.md#L75) and [interactive-mode step 5](../../../skills/using-superra/references/interactive-mode.md#L20-L23) branch off it rather than restating it — interactive's three dispositions now differ (defer keeps `implemented`; skip approves after self-verification). [task-file-contract.md](../../../skills/task-tree/references/task-file-contract.md#L21) carries the matching status-ownership sentence, and §Resuming Work reads `implemented` as "approval decision still open" instead of "to review". The planner side gets one line in [task-tree-design.md](../../../skills/superplan/references/task-tree-design.md#L21-L23): mark high-stakes work with the tier/focus you would want, never schedule review as a task.

**Review-depth record → the commit body.** The rule lives in [using-superra §Commits](../../../skills/using-superra/SKILL.md#L30), one sentence appended to the existing commit-grammar paragraph: a commit landing `status: approved` names the tier and focuses, or that no independent pass ran and approval rests on the approving agent's own verification. Chosen over a task-file field because both possible writers (the reviewer at APPROVE, the orchestrator at self-approval) already commit and already read this always-loaded section — a task-file home would need the same rule stated in two role skills, and would re-add to the task file exactly what the v0.4 reporting contract moved out of it. The record is greppable in `git log` next to the diff it describes.

**Phase-exit gate split out.** superimplement's old Step 3 (reproducibility) and Step 4 (4-option completion menu) moved verbatim to [superimplement/references/completion.md](../../../skills/superimplement/references/completion.md); SKILL.md keeps a one-line Step 3 pointing there, and interactive-mode gained step 7 pointing there too. Without this the default path could not close IMPLEMENT without a `Skill(superRA:superimplement)` call — which would both break the zero-load property and trip the `ensure-agent-orchestration` gate. A reference file is a plain `Read`, so neither happens. Ownership stays with superimplement.

**INTEGRATE safety net made explicit.** [integrate.md Step 6](../../../skills/superintegrate/references/integrate.md#L48-L60) states that its reviewer pass runs regardless of what individual tasks got, and now dispatches `Tier: thorough`.

**Hook verified, not re-scoped.** `hooks/ensure-agent-orchestration` gates only the literal `Skill(superRA:superimplement|superintegrate)` call. The default path never makes that call, so the misfire the objective anticipated does not arise; the gate stays correct because both gated skills always dispatch. `tests/hooks/test-ensure-agent-orchestration.sh` — 15 passed, 0 failed. The hooks doc row now states the invariant (gated skills always dispatch; sometimes-dispatching paths — `superplan`, the interactive loop — instruct the load themselves).

**Doc sweep, same change.** `CLAUDE.md`: "Gates are local discipline" now separates the triggered review decision from the gates a running review enforces; Agent Load Surface splits the phase-skill row (superimplement → on-demand, interactive-mode.md → typical); the ownership row for execution modes names §Deciding on Review and the canvas loop. `README.md` and `docs/site` (site root, quickstart, both `05-workflows` pages, task-tree status/frontier, hooks) previously taught autonomous-by-default and reviewer-APPROVE-required — including the three lines `review-skill` deferred here ([02-quickstart:79](../../../docs/site/02-quickstart/task.md#L79), `05-workflows/02-implement` §Execution modes, [interactive-mode.md:21](../../../skills/using-superra/references/interactive-mode.md#L21)); all now teach interactive-by-default and review-where-it-earns-its-cost, keeping the blind-spot argument for independence. Stale `superimplement` Step-3/Step-4 citations re-pointed in `CATEGORIES.md`, `econ-data-analysis`, `theory-modeling` (3 files), `superintegrate/references/finish.md`, `agent-orchestration` §Seat Assignment, and `codex-instructions.md` (interactive is the default cadence there too, and distinct from `harness-forced-inline`).

### Validation

**Trace 1 — executed, live.** A fresh Claude Agent-SDK session (sonnet) over a scratch two-task tree, prompt `superra: work the frontier of the task tree in this repo.`, with `PreToolUse` hooks recording every `Skill`, `Task`/`Agent`, and tool event. Result: skill loads `["superRA:using-superra", "superRA:implement-task"]` — **no `superRA:superimplement`** — and **`dispatches: []`**. The agent did the work itself, committed, then closed with a review recommendation and a three-way ask ("skip / review / defer"), naming `thorough` + `correctness`/`scope-fidelity` as what it would use if asked. It also loaded `superRA:implement-task`, which step 3 of the loop requires (the reporting contract lives there); [interactive-mode.md:14](../../../skills/using-superra/references/interactive-mode.md#L14) now forbids only filling a seat or running a role protocol, so the two lines no longer read as a contradiction.

**Trace 2 — attempted, invalid, not retried.** The broad-frontier session left its scratch fixture and operated on this repo's own worktree instead (it resolved the real task tree, wrote this task's `## Results`, and committed the in-flight diff as `7014a366`; that commit was reset and this Results section rewritten from verified evidence). The trace therefore proves nothing about the recommendation behavior, and live tracing was stopped rather than risk a second escape. The escape itself — mechanism undiagnosed, plausibly `superRA/superra` resolving the task root from the tool source rather than cwd — is owned by [task-tree/agent-cwd-isolation](../../task-tree/agent-cwd-isolation/task.md).

**Trace 3 — not executed.** Reasoned only: the review-recommendation path is [§Deciding on Review](../../../skills/using-superra/references/main-agent.md#L58-L66) plus the interactive loop's step 5, and trace 1 did produce a tier-and-focus-naming recommendation on a low-stakes task. No live high-stakes trace was run.

**Accepted validation debt.** Two of the objective's three traces were never executed: the broad-frontier subagent-mode *recommendation* trace, and the high-stakes *review* recommendation trace. Both need a live agent session, and live tracing from this task is blocked until the cross-checkout escape is fixed — a second escape can commit to an arbitrary checkout. The re-run rides with [task-tree/agent-cwd-isolation](../../task-tree/agent-cwd-isolation/task.md); nothing in this branch verifies those two behaviors beyond the instruction text.

The live smoke covers the review-requested path, not the no-review path this change makes the default: its orchestrator prompt supplies the researcher-request trigger so the reviewer-seat dispatch stays covered. Keeping that coverage was the deliberate call — a shallow sentinel task gives an autonomous run no reason to review, so asserting the no-review path there would trade real dispatch coverage for a weak assertion. The default path therefore has no live-smoke coverage; it rides with the same isolation task.
