## Objective

The PreToolUse gates deny every bypass the review confirmed, across all three harness registries, with a denying regression test per bypass.

- One shared apply_patch parser — new `skills/task-tree/scripts/_apply_patch.py` — replaces the three hand-rolled copies (`task_approval_gate.py`, `task_hook.py`, `communicate_gate.py`), handling `Add/Update/Delete File` and `Move to:` headers.
- Hunk lines starting with neither `+` nor `-` — including the empty string — are context; each hunk matches from position 0, not only forward from the previous hunk.
- The approval gate fails closed on task.md targets: when it cannot reconstruct the patch result, it denies if the patch's added lines set `status: approved` and the file's `## Review Notes` carries `[BLOCKING]`. Same conservative deny for Bash in-place mutations (redirect, `tee`, `sed -i`, `cp`/`mv` targets), whose results are never reconstructable.
- The communicate gate counts only read evidence as a skill load: the exact `skill`-field match, Read-tool `file_path` records, and shell segments starting with a read verb (`cat`, `head`, `bat`, `less`, `sed -n`) targeting `skills/communicate/SKILL.md`. Mentions in `git diff`, `grep`, or other commands do not clear the gate. Subagent detection is `agent_id or agent_type`.
- Registry sweep: `hooks-codex.json` ensure-communicate (PreToolUse) and task-hook (PostToolUse) matchers gain `apply_patch`; guard-task-approval gains `Bash` in all three registries; `hooks-cursor.json` gains agent-model-guard.
- Shim cleanups: the identical 18-line gate shims dedupe into a shared `hooks/run-python-gate` (wrapper files kept so registry entries and executable bits are unchanged); `hooks/agent-model-guard` drops the `cat`/`printf` stdin buffering and execs python3 reading stdin directly.

## Results

- All five confirmed gate bypasses now deny, each with a reproducing regression test; the full `skills/task-tree/scripts` pytest suite (815 tests) and every `tests/hooks/` suite pass.
  - The shared parser [_apply_patch.py](../../../../skills/task-tree/scripts/_apply_patch.py) replaces the three hand-rolled copies; blank-context lines parse as context and each hunk matches from position 0 (`test_task_tree.py::TestApplyPatchParser`).
  - The approval gate fails closed: an unreconstructable patch whose added lines set `status: approved` while the file's `## Review Notes` carries `[BLOCKING]` denies. Bash in-place mutations (redirect, `tee`, `sed`/`perl` `-i` including flag clusters, `cp`/`mv` targets) get the same conservative deny — it fires only when the command text itself sets `status: approved`, so a flip spelled without the literal string passes and the PostToolUse validator warning is the backstop. The deny message says to split the status flip from the notes edit.
  - The communicate gate counts only read evidence — the exact `skill` field, Read-tool `file_path` records, and read-verb shell segments (`cat`/`head`/`bat`/`less`/`sed -n`) targeting the SKILL.md; `git diff`/`grep` mentions no longer clear it. Subagent detection is `agent_id or agent_type`. Accepted residual: a genuine Read of the SKILL.md still counts as loaded.
  - Registry sweep: `hooks-codex.json` ensure-communicate, task-hook, and guard-task-approval matchers gain `apply_patch`; guard-task-approval gains `Bash` in `hooks.json` and `hooks-codex.json` (`hooks-cursor.json` is matcher-less and already runs it); `hooks-cursor.json` gains agent-model-guard.
  - The three gate shims source a shared [run-python-gate](../../../../hooks/run-python-gate) — sourced rather than exec'd through `bash`, since hook runners provide a sparse PATH without it (caught by `test-codex-hooks.sh`); agent-model-guard's inline python moved to [agent_model_guard.py](../../../../hooks/agent_model_guard.py), which reads stdin directly with no `cat`/`printf` buffering.
  - Matcher-pinning tests updated to the new registry shape: `test-ensure-communicate.sh`, `test-guard-task-approval.sh`, `check-harness-compatibility.sh`, `test_task_tree.py`, `test_contract.py`, `load_contract.json`, and the Codex e2e/smoke fixture generators.

## Review Notes

Tier: thorough. Focus: correctness. Verified by re-running every `tests/hooks/` suite plus the `skills/task-tree/scripts` pytest suite, and by driving both gates with hand-built payloads for patch shapes, Bash forms, and transcript-evidence shapes beyond the pinned cases. The five confirmed bypasses all deny. The advisories below are residual holes and false denies that probing turned up; none defeats a pinned case. (This section spells the blocking marker out of band on purpose — see item 6.)

1. [ADVISORY] → fixed: `_IN_PLACE_MD_RE` now matches a flag cluster containing `i`, with denying cases in both gate test suites. `perl -pi -e` is invisible to the shared Bash target extractor. [_apply_patch.py:150-153](../../../../skills/task-tree/scripts/_apply_patch.py#L150-L153) requires a standalone `-i` token, so `bash_markdown_mutation_targets("perl -pi -e 's/a/b/' x.md")` returns `[]` while `perl -i -pe …` returns `['x.md']`; the approval gate correspondingly allows `perl -pi -e 's/status: revise/status: approved/' superRA/…/task.md` and denies the `-i -pe` spelling. `-pi` is the more common idiom. The pattern is a verbatim move of the pre-hardening communicate-gate regex, so the gap is inherited, but it is now load-bearing for the approval deny too. Fix: match a flag cluster containing `i`, e.g. `-[a-zA-Z]*i[a-zA-Z]*\b`.
2. [ADVISORY] → fixed: the Results bullet now states the literal-string precondition and names the PostToolUse validator as the backstop. The Bash deny is keyed on the literal string `status: approved` appearing in the command ([task_approval_gate.py:156](../../../../hooks/task_approval_gate.py#L156)), so a flip spelled without it passes: `sed -i '' 's/revise/approved/' superRA/…/task.md` returns `{}` against a task whose review notes carry a blocking marker. This is the literal reading of the Objective's "same conservative deny" — the apply_patch fallback keys on added lines the same way — so it is by design. The Results bullet, though, reads as if every in-place Bash mutation of a blocking task denies; qualify it to say the deny fires only when the command text itself sets `status: approved`.
3. [ADVISORY] → recorded residual: accepted with the PostToolUse `validate_review_notes` warning as the backstop; widening the fallback beyond the add-approved direction is out of this task's scope. The fail-closed fallback covers one direction only. [task_approval_gate.py:139-144](../../../../hooks/task_approval_gate.py#L139-L144) denies unreconstructable patches that *add* `status: approved`; a hunk with no context lines that appends a new blocking finding to an already-`approved` task reconstructs to `None` ([_apply_patch.py:121-123](../../../../skills/task-tree/scripts/_apply_patch.py#L121-L123)) and passes, reaching the same approved-plus-blocking state from the other side. A context-bearing version of the same patch denies. Backstop: the PostToolUse `validate_review_notes` warning still fires on the resulting file.
4. [ADVISORY] → fixed: `tail` added to `_READ_VERBS` and the `sed` check accepts a flag cluster containing `n`; both reads now count as load evidence in the test suite. Two ordinary reads of the SKILL.md now deny in the communicate gate. `_READ_VERBS` at [communicate_gate.py:18](../../../../hooks/communicate_gate.py#L18) lists `cat`/`head`/`bat`/`less` but not `tail`, and the `sed` check at [communicate_gate.py:147](../../../../hooks/communicate_gate.py#L147) tests for a standalone `-n`, so `sed -ne '1,50p'` fails it. In a transcript carrying nothing else, both `tail -50 skills/communicate/SKILL.md` and `sed -ne '1,50p' skills/communicate/SKILL.md` produce a deny. Add `tail` to the verb list and test the `sed` flags as a cluster.
5. [ADVISORY] → fixed. Removing `_APPLY_PATCH_FILE_RE` left no blank line between `_PLAN_TOKEN_RE` and the next def — [task_hook.py:253-254](../../../../skills/task-tree/scripts/task_hook.py#L253-L254). Restore the two-blank-line separation.
6. [ADVISORY] → fixed: the deny message now says the gate cannot tell a quoted marker from a live finding and to spell quoted markers out of band. A reviewer cannot quote the blocking marker inside the review notes of a task being approved: the gate matched the marker in this section's own prose and denied the approving edit, which is why the text spells it out instead. The gate cannot tell a quoted marker from a live finding, so this is inherent to the invariant rather than a defect — worth a line in the deny message so the next agent recognizes it instead of retrying.
