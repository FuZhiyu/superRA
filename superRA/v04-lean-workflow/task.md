## Objective

Redesign the superRA workflow for frontier-model economics: retire the dedicated role agents in favor of role skills, make independent review triggered rather than mandatory, make interactive the default execution mode, and enforce a concise-writing and reporting contract that ends duplicated, over-long task files and conversation re-narration.

### Context

Design contract for every subtask:

- Roles become skills: dispatched general-purpose agents load role skills; the `agents/` prototype specs and their Codex generation plumbing are retired.
- Review is triggered, not scheduled: implementer self-check always; independent review only on user request, a planner high-stakes mark, or an implementer concern/uncertainty return; one thorough pass at the INTEGRATE boundary remains the safety net.
- Interactive is the default execution mode; subagent mode runs on user request or agent recommendation — recommend with a one-line rationale, never silently switch.
- Scope discipline: deliver what was asked at the scope intended unless the task is explicitly open-ended.
- Task files are the primary documents and hold only what must be preserved; conversation carries deltas and pointers; possibly-relevant extras go to conversation first and enter the task file only if the researcher wants them.
- Teach principles with an example or two, in the register they prescribe, placed where agents already are when the behavior applies — not enumerated rule catalogs.
- Checklist recalibration collapses severities to blocking/advisory and deletes verification scaffolding; no "what not to flag" exclusion lists.
- Out of scope for v0.4: rewriting the showcase/docs-site exemplars and hygiene cleanup of this repo's existing task files.

Evidence base: [review-prompting research](attachments/research-review-prompting.md), [concise-writing research](attachments/research-concise-writing.md), [review-architecture map](attachments/map-review-architecture.md), [writing-surfaces map](attachments/map-writing-surfaces.md).

### Constraints

- This repo's `CLAUDE.md` contributor gates (DRY/Necessity line tests) apply to every subtask; the task that invalidates a `CLAUDE.md` ownership row, Agent Load Surface entry, or `README.md` statement updates it in the same change.
- `.codex/agents/*.toml` are generated by `skills/codex-superra-setup/scripts/sync_codex_agents.py`; retire or regenerate through the generator, never hand-edit.
- The harness-instruction-following test suite (`tests/harness-instruction-following/`) cites role-spec files and line ranges; keep it green in whichever task moves what it cites.

Planning review (handoff-readiness), 2026-08-01. Verdict: REVISE — item 1 blocking, items 2–4 advisory.

1. **[BLOCKING] Invalidated-statement coverage is narrower than the evidence base's change inventory.** The parent `### Constraints` bullet covers only "a `CLAUDE.md` ownership row, Agent Load Surface entry, or `README.md` statement", but [map-review-architecture.md](attachments/map-review-architecture.md) §6 tier 5 and its Key tensions show the redesign also invalidates CLAUDE.md design-philosophy lines and docs pages no subtask reaches: [CLAUDE.md:35](../../CLAUDE.md#L35) "Gates are local discipline … review gates … are enforced" (directly contradicts triggered review; the map flags it "must be revised alongside the policy change"), [CLAUDE.md:37](../../CLAUDE.md#L37) "Compose at the workflow edge … the role spec" (role specs are retired), and the `docs/site` implement/integrate pages describing the mandatory review loop. [review-policy/task.md](review-policy/task.md) names no doc sweep and its guidance points only to map §2; [role-skills/task.md](role-skills/task.md) names only the ownership table + Agent Load Surface (contrast [mode-default/task.md](mode-default/task.md), which names its own invalidated-statement sweep). Fix: widen the constraint to any invalidated `CLAUDE.md` / `README.md` / `docs/site` statement updated in the same change, or add the specific surfaces to `review-policy` and `role-skills` with a pointer at map §6 tier 5.
2. **[ADVISORY] `planning-review.md` severity alignment is triple-attributed.** [review-calibration/task.md](review-calibration/task.md) validation requires it share the vocabulary, [checklist-recalibration/task.md](checklist-recalibration/task.md) lists planning-review among the checklists it aligns, and [review-policy/task.md](review-policy/task.md) guidance says the change is "owned by `review-calibration`". Worst case is idempotent duplicate work, but pick one owner and make the other two statements point at it.
3. **[ADVISORY] Unordered same-file overlap on `refactor-and-integrate/SKILL.md`.** [writing-contract/task.md](writing-contract/task.md) moves the final-diff-self-check trail to the commit body while [checklist-recalibration/task.md](checklist-recalibration/task.md) prunes the same checklist; the two sit on disjoint dependency chains (`role-skills` vs `review-calibration`) so they can run in parallel against the same region. Add an ordering edge or a one-line ownership delimiter (e.g. checklist-recalibration leaves the self-check-trail item to writing-contract).
4. **[ADVISORY] `hooks/ensure-agent-orchestration` unassigned under the new default.** The hook gates the `agent-orchestration` load for `superimplement`, and the map lists it (§6 tier 4) as changing "if the gate changes"; with interactive-as-default and zero dispatches its mandate misfires.
