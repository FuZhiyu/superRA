## Objective

Redesign the superRA workflow for frontier-model economics: retire the dedicated role agents in favor of role skills, make independent review triggered rather than mandatory, make interactive the default execution mode, and enforce a concise-writing and reporting contract that ends duplicated, over-long task files and conversation re-narration.

### Context

Design contract for every subtask:

- Roles become skills: dispatched general-purpose agents load role skills; the `agents/` prototype specs and their Codex generation plumbing are retired.
- Review is triggered, not scheduled: implementer self-check always; independent review only on user request, a planner high-stakes mark, or an implementer concern/uncertainty return; one thorough pass at the INTEGRATE boundary remains the safety net.
- Interactive is the default execution mode; subagent mode runs on user request or agent recommendation — recommend with a one-line rationale, never silently switch.
- Scope discipline: deliver what was asked at the scope intended unless the task is explicitly open-ended.
- Task files are the primary documents and hold only what must be preserved; conversation carries deltas and pointers; possibly-relevant extras go to conversation first and enter the task file only if the researcher wants them.
- Teach principles with an example or two, in the style they prescribe, placed where agents already are when the behavior applies — not enumerated rule catalogs.
- Checklist recalibration collapses severities to blocking/advisory and deletes verification scaffolding; no "what not to flag" exclusion lists.
- Out of scope for v0.4: rewriting the showcase/docs-site exemplars and hygiene cleanup of this repo's existing task files.

Evidence base: [review-prompting research](attachments/research-review-prompting.md), [concise-writing research](attachments/research-concise-writing.md), [review-architecture map](attachments/map-review-architecture.md), [writing-surfaces map](attachments/map-writing-surfaces.md).

### Constraints

- This repo's `CLAUDE.md` contributor gates (DRY/Necessity line tests) apply to every subtask; the task that invalidates any `CLAUDE.md`, `README.md`, or `docs/site` statement — ownership rows, Agent Load Surface entries, and design-principle prose alike — updates it in the same change (inventory: [map-review-architecture.md](attachments/map-review-architecture.md) §6 tier 5).
- `.codex/agents/*.toml` are generated by `skills/codex-superra-setup/scripts/sync_codex_agents.py`; retire or regenerate through the generator, never hand-edit.
- The harness-instruction-following test suite (`tests/harness-instruction-following/`) cites role-spec files and line ranges; keep it green in whichever task moves what it cites.

## Results

The v0.4 release, described for users in [RELEASE-NOTES.md](../../RELEASE-NOTES.md). Four things changed at once: who runs a task, when it gets reviewed, how much anyone writes about it, and how big a task is.

- **Roles are skills.** [implement-task](../../skills/implement-task/SKILL.md) and [review-task](../../skills/review-task/SKILL.md) carry the protocols; a dispatch names the skill and the harness's default agent fills the seat, so Claude Code and Codex share one dispatch mechanism. The `agents/` prototype specs, the generated Codex named agents, the `codex-superra-setup` generator, and the canonical-role resolver are gone — see [role-skills](role-skills/task.md).
- **Review is triggered, not scheduled.** [main-agent.md §Deciding on Review](../../skills/using-superra/references/main-agent.md) is the single home for the call; `implemented` now means "approval decision still open", and with no independent pass the orchestrating agent verifies the work itself and records that in the commit. Interactive execution became the default in the same change — see [workflow-defaults](workflow-defaults/task.md).
- **A review is a scoped pass.** `Tier:` and `Focus:` are optional dispatch fields with `quick` and `correctness` defaults; verification is evidence-first, re-execution is a bounded exception, and every finding carries a citation. CRITICAL/MAJOR/MINOR collapsed to `[BLOCKING]`/`[ADVISORY]` repo-wide, with the checklists recalibrated from 294 to 259 blocking items — see [review-skill](review-skill/task.md).
- **One writing contract.** [communicate](../../skills/communicate/SKILL.md) is always loaded and owns human-facing selection, structure, rewriting, distillation, and Markdown mechanics; `report-in-markdown` is retired into it and the academic-prose skill is renamed [academic-writing](../../skills/academic-writing/SKILL.md). Hooks enforce it before every Markdown write — see [reporting-contract](reporting-contract/task.md).
- **Planners cut by edit surface.** Children editing the same files or reloading the same context are one task; the granularity self-review item prescribes merging as well as splitting, and no numeric task-count cap was introduced — see [planning-sizing](planning-sizing/task.md).
- **Skill prose is terse everywhere**, with the style spec and the "Teach the Protocol" gate in [CLAUDE.md](../../CLAUDE.md) to keep it that way — see [terse-skill-style](terse-skill-style/task.md).

The evidence base is retained under [attachments/](attachments/): the [review-prompting](attachments/research-review-prompting.md) and [concise-writing](attachments/research-concise-writing.md) research, the [review-architecture](attachments/map-review-architecture.md) and [writing-surfaces](attachments/map-writing-surfaces.md) maps, the [Communicate synthesis](attachments/research-communicate.md), and the [over-granularity diagnosis](attachments/diagnosis-overgranular-planning.md) whose ranked edits `planning-sizing` executed.
