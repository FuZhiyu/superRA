# Style

Use this reference for words and sentences. Use [structures.md](structures.md) to arrange the whole message.

## Make each sentence easy to parse

- **Name the actor and action.** Write “The hook blocks the edit,” not “Blocking is performed.” Use passive voice when the actor is unknown or irrelevant.
- **Use the plain precise word.** Prefer a familiar word unless a technical term is more exact. Define an unfamiliar term at first use.
- **Use one name per concept.** Do not rotate synonyms or invent abbreviations for variety.
- **Write short, complete sentences.** Keep cause, contrast, conditions, and sequence explicit; do not compress them into fragments or arrow chains.

## Cut without hiding meaning

- **Remove empty framing.** Cut introductions, recaps, success narration, and importance claims that delay the point without changing it.
- **Keep one useful example.** Add another only when it teaches a different case.
- **Preserve precision and voice.** Keep necessary articles, technical terms, hedges, first-person voice, emphasis, rhythm, and punctuation.

## Check the result

- A cold reader can name the actor, action, and relationship in each sentence.
- Each unfamiliar term is defined, and each concept keeps one name.
- The text passes the core [useful-content test](../SKILL.md#keep-only-useful-content).
- Shortening the text did not strengthen a claim, hide a caveat, or flatten the author's voice.
